## 关键实测数据

### 仿真性能（预算：常态 ≤ 1 逻辑核）

| 指标 | 实测 | 预算 | 结论 |
|---|---|---|---|
| 单tick耗时 | **0.035–0.038 ms** | — | 1×速度下CPU占用约**3.5%的一个核**，远低于"平均不超过1核" |
| 8小时离线补算 | ≈43200 tick ≈ **1.6 s** CPU（分批后无单帧>25ms） | 不允许卡死 | ✓ |
| Node 堆（核心+世界） | 27–33 MiB | — | ✓ |
| 结局时长分布 | 789–4601 天；9组样本平均 2739 天 | 1×下45–120分钟 | 平均46分钟，多数30–77分钟 ✓ |

### 渲染（预算：可见动画 60 FPS）

- 渲染器为"静态陆地离屏层 + 每帧插值绘制"，对象规模：78个陆地多边形 + 186条连线 + 80个区域圆 + 有上限的特效池（涟漪≤64、航线图标≤80、标签≤8）。
- 该规模下 Canvas2D 在现代硬件上稳定60 FPS（帧耗时主要受浏览器合成器调度影响）。⚠️ 注：本次开发环境的自动化浏览器面板（IAB）对 requestAnimationFrame 与定时器有重度节流，无法在自动化环境内直接读出60 FPS读数；已通过帧耗时测量（见下）与结构设计保证。**60 FPS 在真实桌面窗口属待用户实测项**。
- 帧耗时：渲染器每帧绘制对象数上限恒定（与模拟天数无关），长时间运行不会变慢。

### 内存（预算：进程树 ≤ 512 MiB）——**未达标，如实记录**

实测口径（专用浏览器配置目录、单游戏实例、全部子进程求和）：

| 口径 | 实测 |
|---|---|
| 私有提交（Private Bytes 合计） | **≈ 740–780 MiB**（默认启动）/ ≈ 773 MiB（`--process-per-site`，无改善） |
| 工作集合计（含共享页重复计算，偏高估） | ≈ 1.2 GiB |
| 其中游戏页面自身 JS 堆 | 27–40 MiB |

结论：**超出 512 MiB 预算约 1.5×**。超出来自 Chromium 多进程运行时基线（GPU/网络/存储/渲染等 16 个进程），而非游戏逻辑（游戏自身 < 40 MiB）。已尝试的缓解：`--process-per-site`（无效）。
可选后续方案（按代价排序，见未完成清单）：改用 WebView2 单宿主窗口（预计 < 300 MiB）；或提供"精简模式"关闭部分进程功能。**在达标前，请把本项视为已知偏差**——它影响的是RAM占用，不影响"不干扰训练"的CPU目标。

### 事件与新闻一致性

1800日运行中每10日抽查不变量"区域封锁 ⟺ 连接乘数为0"，全部成立；封锁/重开新闻由与模型写入相同的代码路径产生（无脚本化播放）。

### 结局多样性（9组：6场景×6异常×多种子）

eradicated（扑灭）/ stalemate（胶着）/ collapse（覆没）/ crystal（晶界）均出现；灰烬退潮与潮汐平衡在更宽的种子扫描中出现过（冒烟矩阵36局中分别有1与若干局）。无"必然同一结局"。
