### 压测抓出并修复的缺陷（修复后全量复跑通过）

1. **`saveWorld` 不递增 `seq`**：双槽 seq 打平时 `loadWorld` 的稳定排序会选中较旧槽（Node 侧因测试手工 `seq++` 而未暴露；浏览器 200 轮存读 200 败暴露）。→ 修复：保存即递增，平局再比时间戳。
2. **`seq` 混入状态载荷**：修复 1 后"保存前快照 ≠ 读回快照"（载荷内 seq 永远差1）。→ 修复：`seq` 是存档信封元数据，移出 `serialize`。
3. **`wallAnchor` 位运算截断**：`o.wallAnchor | 0` 把 13 位毫秒时间戳截成 int32 负数（Node 测试中恰为 0 未暴露）。→ 修复：完整精度数值恢复。**此缺陷会破坏"锚点先行"的重复推进防护**——浏览器真实环境下若不修，恢复时可能以错锚点补算。
4. **事件依赖临时钩子**：`pilgrimage` 事件使用 `eventTick` 循环内的临时 `w._rngEvNext()`，脱离循环调用 `apply` 即崩（随机演化S7强制触发抓出）。→ 修复：事件一律使用签名传入的 `rng`，删除临时钩子。
5. `pathToFileURL` 拼接与残留浏览器进程锁 profile → 基准脚本健壮性修复（不影响游戏本体）。

> 以上 1–4 均为"序列化/整数纪律/隐式上下文"类真实缺陷，被压测与真实浏览器双通道暴露；修复后：常规回归 **26/26**、无头压力 **10/10**、浏览器基准全绿（BENCH PASS）。

## 三、结论

- **CPU 预算**：常态 ≈3.5% 单核（1×），2万日浸泡与10万tick交错压测无劣化、无泄漏——"不干扰后台训练"成立。
- **渲染预算**：无GPU（纯CPU栅格化）下单帧 0.5–0.8ms，真实窗口 RAF 实测 152 FPS——60 FPS 目标在最坏渲染路径下成立；已追加 **`启动微疫世界_无GPU.bat`**（`launch.ps1 -NoGpu`）供 GPU 被训练占满时使用。
- **正确性**：压测暴露的 3 个序列化/锚点缺陷全部修复，修复后三套验证（常规26项 / 无头压力10项 / 浏览器基准）全绿。
- **内存**：浏览器运行时基线（≈740–780 MiB 私有提交）仍超 512 MiB 预算，属引擎本体而非游戏逻辑（见测试结果.md），维持未完成清单记录。
